ВЕРСИЯ 1.1.0 — исправления HTTP и Event Log

БИТРИКС24 — ОТЧЁТ ПО ВЫБРАННОМУ СОТРУДНИКУ

ЗАПУСК
Распакуйте весь архив в обычную папку Windows и дважды нажмите START_GUI.cmd.
Сервер, Python, Node.js, Excel и сторонние модули устанавливать не нужно.
Используются штатные Windows PowerShell 5.1 и WPF.
Не запускайте приложение прямо из окна ZIP: все файлы должны лежать рядом.

СЦЕНАРИЙ РАБОТЫ: ПАРАМЕТРЫ → ФОРМИРОВАНИЕ → ГОТОВЫЙ РЕЗУЛЬТАТ

1. ЗАПОЛНИТЕ ПАРАМЕТРЫ

Входящий вебхук *
Вставьте рабочий HTTPS-адрес вебхука вашего портала:
https://portal.bitrix24.ru/rest/USER_ID/TOKEN/
Принимаются также окончание profile.json и вариант /rest/api/USER_ID/TOKEN/.
Ввод скрыт. Флажок «Показать адрес» позволяет проверить вставленный URL.

Сотрудник *
НИКТО НЕ ВЫБРАН ПО УМОЛЧАНИЮ.
Нажмите «Загрузить список сотрудников», затем выберите человека в списке.
Список содержит ФИО и ID; можно набирать начало фамилии. Уволенные сотрудники
также загружаются, если видимы владельцу вебхука. При доступном статусе они
помечаются в списке.
Первый сотрудник после загрузки автоматически не выбирается.

Для списка нужен scope user, user_basic или user_brief. Если список недоступен,
можно вручную ввести числовой ID нужного человека. Введённый вручную ID без
доступа к справочнику не проверяется на существование: проверьте его по порталу.
При смене вебхука выбор очищается, чтобы не использовать ID другого портала.

Период событий *
Выберите даты в календарях и время ЧЧ:ММ:СС.
При открытии окна стоят последние два календарных месяца. Кнопка
«Последние 2 месяца» обновляет период относительно текущего времени.
Начало включается; отметка окончания НЕ включается. Чтобы включить целый
последний день, укажите 00:00:00 следующего дня в поле «До».

Часовой пояс
По умолчанию — Москва, UTC+03:00. Можно выбрать другой пояс для границ
периода и отображения дат в готовом отчёте.

Куда сохранить отчёт *
Выберите существующую папку. Внутри будет создана отдельная папка выгрузки.
Уже существующие отчёты новый сбор не перезаписывает.

Дополнительные параметры
• Пояс исходных дат без UTC-смещения — Москва; поменяйте, если портал выдаёт
  локальные даты другого пояса.
• Часов в рабочем дне — 8, для отчёта контроля времени.
• Пауза запросов — 550 мс.
• Попыток при временной ошибке — 4.

Нажмите «Сформировать отчёт». Если обязательные поля не заполнены или
значения неверны, приложение попросит их исправить и останется на первом
экране. Без явно выбранного сотрудника сбор не запускается.

2. ДОЖДИТЕСЬ ФОРМИРОВАНИЯ

Приложение автоматически переходит на экран обработки. На нём видны
состояния источников, ошибки и индикатор работы. Параметры заблокированы
до завершения, чтобы характеристики отчёта не менялись в процессе.
Технический журнал раскрывается по желанию.

Процент не вычисляется: общий объём задач, карточек и комментариев заранее
неизвестен. Окно остаётся доступным. На большом портале сбор может быть долгим.

«Остановить и сохранить» заканчивает текущий запрос и сохраняет частичный
отчёт. Ожидание сетевого запроса может занять до 90 секунд. При закрытии окна
во время работы выполняется та же остановка, затем окно закрывается.

3. ПОЛУЧИТЕ ГОТОВЫЙ РЕЗУЛЬТАТ

После завершения автоматически открывается итоговый экран:
• сотрудник и его ID;
• фактические границы периода и часовой пояс;
• число найденных событий и ошибок;
• расположение файлов;
• кнопки «Открыть готовый отчёт», «Открыть файл для Excel», «Папка результатов».

Основной отчёт — HTML-таблица с поиском: дата, время, действие, объект,
тип подтверждения, подробности и ссылки на сохранённый JSON.
Файл CSV открывается в приложении, связанном с CSV в вашей Windows;
при наличии Excel его можно открыть или импортировать туда.

Если часть источников недоступна, выводится «Отчёт готов, есть пробелы».
Если работа остановлена, результат прямо помечается как частичный.
Отсутствующие данные не подменяются вымышленными событиями.

«Настроить другой отчёт» возвращает к заполнению полей. Сотрудника нужно
выбрать заново; предыдущий пользователь автоматически не подставляется.

ПРОДОЛЖЕНИЕ И ПЕРЕСБОРКА
На первом экране можно выбрать другой режим:

«Продолжить ранее начатый сбор»
Выберите папку конкретной выгрузки с manifest.json. Сотрудник, период и пояса
загрузятся из неё и будут заблокированы для изменения. Нужен вебхук того же
портала и владельца. Сохранённые страницы повторно не запрашиваются.

«Пересобрать сохранённый отчёт без интернета»
Выберите папку с manifest.json. Вебхук не нужен, сеть не используется.
Недостающие страницы будут отмечены как пробелы.
Для актуального нового снимка выбирайте «Создать новый отчёт».

ПРАВА И ПОЛНОТА
Для источников сбора нужны scopes:
main, task, crm, disk, timeman, telephony, bizproc.
Для выпадающего списка сотрудников дополнительно нужен один из scopes:
user, user_basic или user_brief.

Права владельца вебхука ограничивают доступные данные. Администратор
Битрикс24 видит больше, но это не восстанавливает очищенные журналы,
безвозвратно удалённые объекты и отсутствующую историю изменений.
Права администратора Windows для приложения не нужны.

Собираются Event Log, история задач, трудозатраты, CRM-дела, элементы
и комментарии CRM, логи приложений, метаданные Диска, рабочее время,
контроль времени, телефония, шаблоны бизнес-процессов.
Подробности источников и документация — в README_COLLECTOR_RU.md.

ФАЙЛЫ ОТЧЁТА
• timeline.html — основная таблица.
• timeline_employee_ID.csv — таблица для Excel.
• timeline_employee_ID.json — структурированные события.
• summary.json и status.json — характеристики и статусы источников.
• collection_errors.json и rejected.json — ошибки и неразобранные даты.
• raw — страницы API и checkpoint для продолжения.
• gui_run.log — журнал окна при завершении процесса; ограничен по объёму.

ID в имени файла заменяется выбранным идентификатором сотрудника.
Вебхук не сохраняется в настройках и не включается в командную строку:
он передаётся дочернему процессу через его окружение. После завершения
отчёта поле вебхука очищается. Известные URL вебхуков и query-токены
маскируются в журнале. Список сотрудников загружается через временный
файл с ID и именами; после чтения файла приложением он удаляется.
Интерфейс и сборщик не меняют данные и права портала.

ПРОВЕРКА БЕЗ ПОРТАЛА
В PowerShell из папки приложения:
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\bitrix24_gui.ps1 -SelfTest

Проверены: ввод и даты, отсутствие сотрудника по умолчанию, выбор человека,
пагинация списка (включая уволенных), маскирование, передача параметров,
реальный дочерний процесс на синтетических ответах, остановка с частичным
отчётом, параметры продолжения и режима без сети.

Проверки выполнены в PowerShell 7.4.13 на Linux. XAML проверен как XML,
имена элементов и ссылки на них сопоставлены. Реальная отрисовка WPF-окна
и запуск на Windows в доступной среде не проверялись. Для окна нужен
Windows с настольной средой и Windows PowerShell 5.1.

ИЗМЕНЕНИЯ 1.1.0
• Общий штатный HttpClient вместо Invoke-WebRequest: тело ответа сохраняется при 400/401/403.
• Даты запросов Event Log без дробных секунд, по формату документации.
• При отклонении фильтра дат — однократный переход на фильтр сотрудника и локальный отбор периода. Это может быть дольше и сохранять сырые записи за пределами периода.
• Постоянный отказ источника не повторяется для каждого дня.
• При нуле событий и ошибках окно прямо сообщает, что события не получены.
• Добавлен обязательный файл bitrix24_http.ps1; распакуйте весь новый архив в отдельную папку.
• Проверены реальные ответы тестового HTTP-сервера 400/401, JSON и HTML.

Причину старого HTTP401 нельзя восстановить из присланного текстового журнала: там нет тела ответа. Новая версия раскрывает ответ сервера; недостаточные права или недействующий токен исправляются на портале. Подключение к вашему порталу не проверялось.
